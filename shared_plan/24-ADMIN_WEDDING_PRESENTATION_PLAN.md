# 披露宴向け検定おさらい・ランキング発表 UI 計画

> **状態:** P0コード実装完了。単一の永続セッション、管理者認証、スナップショット採点、段階公開、前後の手動進行、投影待機表示、full/short表示モードを実装。会場での物理リハーサルは未実施で、ユーザー判断によりP0受入条件の対象外。本番環境の設定同期・deploy・管理者ログイン確認は未完。P1/P2拡張は後続。

## 背景と目的

披露宴で新郎新婦に関する検定を実施し、成績上位者へ景品を贈る。回答終了後、司会者が管理画面を使って設問を一問ずつ振り返り、正解と解説を案内した後、ランキングを3位、2位、1位の順に発表できる UI を用意する。体験コンセプトは「ふたりの思い出を振り返り、受賞者を祝うミニセレモニー」とする。クイズの答え合わせ、ふたりのエピソード、受賞者の発表と景品授与をひとつの流れとしてつなぐ。

進行は自動再生ではなく司会者による手動操作とする。管理者だけが完全な結果と未発表の正解を取得でき、投影画面には公開済みステップだけを許可する。順位を一度確定した後は進行中に変化しないようにする。披露宴会場のスクリーンで読みやすく、祝いの場に合う演出を備えた発表体験を目指す。

## 現状と前提

- 現在の画面は `/` と `/answer` が中心で、管理者向けページは未実装。
- `openspec/specs/stcirt/spec.md` の R2 / R3 / R5 では、受検中・回答完了時に正誤、解説、点数を公開しない要件がある。新機能でも管理者向け認証を設け、参加者側に未公開情報が漏れない境界を保つ。
- `examQuestions` には正解インデックス `correctIndex` と `explanation` がある。設問順に列挙して進行し、設問数を5問に固定しない。
- `examParticipants` には表示名がある。`examAnswerSubmissions` は参加者、設問 ID 集合、revision、作成・更新時刻を保持し、回答内容は `examSubmissionAnswers` に保存する。
- batch 提出経路は `exam_answer_logs` に単問ログを追記しない。既存ログや回答時刻をランキングの根拠にしない。現状にランキング集計機能はない。
- batch 回答データは設問 ID を持つが、提出時点の問題文・正解・解説のスナップショットを持たない。発表対象の採点を確定するときに、その時点の設問集合・正解・解説・表示名・得点を保存する設計が必要。
- batch 本人復元の応答は displayName を返さない。管理者機能で必要な情報を取得する場合も、既存の参加者向け応答へ未公開情報を追加しない。
- 参加者セッションは表示名と共通4桁 PIN から署名した HttpOnly cookie を使う。これは管理者権限の代用にせず、管理操作向けに別の認証・認可を設計する。
- 現在の seed は IT 検定の5問であり、新郎新婦に関する設問への置き換えはこの UI 計画の対象外。
- 現状に開催回を区別する `eventId` がない。異なる披露宴や試験の回答を混在させない単位を実装前に決める。

## 進行体験

司会者向けの状態遷移は以下を基本とする。設問部分は実際の設問順に繰り返し、最後の設問の後にランキングへ進む。

1. **待機:** 開始前の案内と進行開始操作を表示。
2. **設問のおさらい:** 問題文と選択肢を表示。参加者に考えてもらう時間を司会者が取れる。
3. **正解・解説:** 正解を視覚的に強調し、登録済み解説を表示。
4. **ランキング導入:** 結果発表への案内を表示。
5. **3位発表 → 2位発表 → 1位発表:** 順位ごとに名前と得点を公開する。
6. **祝福・終了:** 全順位発表後の締め画面を表示。

各状態に具体的な進行操作（例:「正解を発表」「3位のお名前を発表」）、前へ戻る操作、現在の段階、次に何が表示されるかの控えめなプレビューを用意する。前後操作は永続化された段階カーソルだけを動かし、確定済み採点スナップショットを変えない。司会者用プレビューには現在・次の表示を出し、未発表情報は投影画面に含めない。進行中の主操作は誤操作しにくい位置と大きさにする。投影を一時的に隠して `{ state: 'standby' }` だけを表示する待機操作と、現在段階を再表示する操作を用意する。毎回の遷移に確認ダイアログを挟まず、最初からやり直す操作や採点結果の再確定など、状態を失う操作だけ確認を求める。

### 表示・演出

#### 画面の絵コンテ

| 段階 | 投影画面の主役 | 進行・演出 |
| --- | --- | --- |
| 開始 | タイトル、ふたりの名前、任意の写真 | 司会者が開始。写真がなくても成立する。 |
| 設問 | Q n/N、問い、すべての選択肢 | 参加者に考える時間を取る。選択肢ごとのクリックを要求しない。 |
| 正解 | 正解テキストと該当選択肢 | 正解を一度に見せる簡易モードも用意する。 |
| 解説 | 現行の登録済み解説文を最大4行で表示 | 司会者は管理画面で現行の解説全文を確認する。別の投影用要約・司会メモはP1で導入する。 |
| ランキング導入 | 結果発表への案内 | 受賞者名や点数はまだ出さない。 |
| 順位の予告 | 「第3位の発表です」など順位だけ | 名前と得点は伏せ、予告ステップで未発表結果を投影側へ送らない。 |
| 受賞者発表 | 順位、名前、得点 | 司会者の意図ある1クリックで当該受賞者を公開。名前と得点を主役にする。 |
| 景品授与 | 発表済みの受賞者と授与案内 | 次順位へ自動で進まず、拍手・移動・景品授与の間は画面を保持する。発表済み受賞者を小さく残すのは任意。 |
| フィナーレ | 受賞者3名と感謝の言葉 | 3名での写真撮影を促し、全ゲストへの感謝で締める。 |

P0では既存の `explanation` をそのまま投影画面に最大4行で表示し、管理画面では全文を確認できるようにする。P0で解説の要約を生成したり、別の要約・読み上げメモを要求したりしない。P1では必要に応じて投影用要約と司会者用メモの別フィールドを追加し、公開前の内容確認・承認を運用に含める。

#### 視覚・アクセシビリティ

- **暫定デザイン値:** 16:9 を主基準とし、端から表示領域の約5%を安全余白にする。アイボリー地に深い文字色を置き、シャンパンゴールドは装飾に使う。写真に文字を重ねない。別の投影方式や4:3への対応は未決事項として残し、レターボックス時も安全余白を守る。
- 1080pでの仮目安は名前・順位72–120px、問い48–64px、本文32–40px。これは本計画の暫定値であり、一般的な推奨値ではない。CSS の印刷用 pt サイズを流用せず、会場後方から実機で読んで調整する。
- 通常文字はコントラスト比4.5:1以上、大きな文字は3:1以上を最低基準とする。金色は装飾用とし、小さい文字に使わない。順位は色だけで区別せず、順位番号と文字ラベルを併記する。
- 遠くから読める文字、余白、短い要点を優先する。色や写真は祝宴らしさを添えるために使い、情報の判読性を損なわない。

#### 操作と演出

- 司会者画面では現在・次のステップ、P0の現行解説全文、具体的な主操作を見せる。P1で司会者用メモを追加する場合は解説と別に管理する。キーボードの矢印キーによる進行を任意で用意する場合、押しっぱなし・連打を抑え、フォーム入力中はショートカットを無効にする。進行を担当する人は一人とし、投影接続と最新状態を開始前に確認できるようにする。
- 投影画面を待機表示に隠す、全画面にする、休止状態を防ぐ操作を用意する。表示モードは `full`（既定）と `short` を永続保存し、開始前にも設定できる。`short` は回答段階で解説を省略するだけの表示モードとし、設問→正解→順位発表の手動段階や前後移動、待機/再表示は省略しない。
- 順位発表は1クリックで名前と得点を公開し、短い装飾演出は自動で終わる。遷移0.3–0.6秒、祝いの演出1–2秒は案件固有の仮値で、会場の実機で調整する。演出中もスキップまたは非表示にできる。
- 次の順位へ自動遷移しない。拍手、移動、景品授与、撮影のために発表画面を保持できる。1位は時間を強制せず、余白や静的な照明風装飾で特別感を出す。カウントダウンは初期必須にしない。
- 動きを減らす設定を尊重し、演出の一時停止・停止・非表示を用意する。音声はP1の任意機能とし、初期状態はオフ、明示操作でのみ再生する。ミュート・停止操作を用意し、音が出なくても進行できるようにする。ブラウザーの自動再生制限があっても画面の状態遷移を止めない。
- 静的な写真等は先読みできるが、未公開の正解や順位を投影データに先読みしない。投影画面の再読み込み後もサーバーが保持する最新の公開状態を復元する。

#### 優先度

- **P0（披露宴で成立する必須範囲）:** 手動で前後できる進行、`full` / `short` 表示モードの永続設定、正解強調と短縮時の解説省略、投影の可読性と待機/再表示、管理者認証、採点結果の確定、再読み込み・再接続後の復帰、景品授与中の画面保持、予告から発表への段階的公開。
- **P1（素材や会場に応じた拡張）:** 写真・コメント、発表時のみの任意音声、正解後の匿名回答分布・正答率。分布は少人数で個人を推測されるおそれがある場合に非表示または集約し、順位を先に示さない。
- **P2（後続の拡張）:** 高度なテーマカスタム等。初回から過剰なクリック演出やアップロード管理を必須にしない。

## ランキング確定ルール

- 発表開始時に `exam_questions` を `id ASC` ですべて読み、全参加者と各参加者の有効な最新完全提出（対象設問集合に一致する回答）を同一 SQLite transaction 内で確定する。設問集合や参加者を管理画面で別指定する開催単位は設けず、データベース上の単一現在セッションを使用する。
- 有効な完全提出がない参加者もランキングに含め、全問未回答相当の0点とする。最新 revision が現在の全設問に有効でない場合、現在の設問集合に一致する最新有効提出を使い、それもなければ0点とする。
- 得点は正答1問につき1点、未回答は0点とする。100点換算、配点、部分点は導入しない。
- 順位は標準競技順位とする（例: 1, 1, 3）。同点者は全員を同順位として同じ操作で公開し、時刻や参加者IDによるタイブレークはしない。
- 発表開始時に対象設問、正解、解説、表示名、回答スナップショット、得点、順位を保存する。発表中に回答変更や設問編集が起きてもスナップショットを変えない。
- 3位、2位、1位の順に発表する。該当順位がない段階はスキップする。受賞者数が3人を超える場合も、その順位の同点者全員を発表する。
- 一度開始した単一現在セッションはAPIからリセット・再確定しない。運用時の再開催と開催間の切替はP1以降の決定事項とする。

## 実装方針

1. **決定:** ひとつのSQLite永続セッションを使う。開催・設問集合の管理は今回設けず、開始時点で全 `exam_questions` と全参加者を固定する。
2. **決定:** `ADMIN_PRESENTATION_PIN` と `ADMIN_PRESENTATION_SESSION_SECRET` で参加者認証と独立したHttpOnly署名cookieを発行し、Origin検証を行う。未設定時はfail closed。
3. **決定:** 1問1点、未回答0点、標準競技順位を用い、全同点者を同順位で発表する。最も新しい有効な完全保存回答を採点する。
4. **決定:** `operationId` による同一操作再送の冪等性とversion条件付き状態更新を使う。`advance` / `previous` はサーバーの永続stage cursorだけを動かし、採点snapshotは変えない。最初の状態で `previous` は409とし、`finished` からは3位→2位→1位の発表順で最後に存在した順位へ戻る（入賞者なしなら `podium_preview` へ戻る）。
5. **決定:** `hide` / `show` で永続 `projectionHidden` を切り替える。待機中の公開projectionは `{ state: 'standby' }` だけを返す。開始前から待機を設定でき、再表示で現在の進行段階に戻る。
6. **決定:** 表示モード `full` / `short` はDBに永続化し、既定は `full`。開始前・進行中とも `setMode` で切り替えられる。短縮モードでも設問→正解の手動2段階、順位の3位→2位→1位手動発表、前後移動、待機/再表示、採点snapshotを維持する。
7. 投影 API は管理者向けの完全な結果から許可済みの段階だけを明示して返す。質問段階では正解・解説を含めない。回答段階は常に `correctAnswer` / `correctIndex` / `choices` を含み、`full` では既存解説も返すが、`short` では `explanation` property自体を省略する。順位予告には受賞者を含めない。
8. P0の範囲で操作画面と投影画面を実装し、絵コンテの状態と公開境界を一致させる。管理画面では現在・次の位置と解説全文、投影画面ではその段階で許可された情報だけを表示し、`full` の解説は最大4行で表示する。別の投影用要約と司会メモはP1とする。
9. `openspec/specs/stcirt/spec.md` の Requirements / API / Components / データモデルを追加・変更内容と同期する。Next.js のコードを書く前に `node_modules/next/dist/docs/` の関連ガイドを読み、現行バージョンの規約に従う。
10. 会場の物理リハーサルは任意の参考確認として扱い、画面サイズ、文字、テンポを実機で調整する場合は下記手順を使う（本作業では未実施、受入条件外）。

- 予告画面、前へ戻る操作、投影待機/再表示、投影リロードで未発表の順位・名前・正解が見えないことを確認する。
- 音なし、動きを減らす設定、演出スキップで全進行が成立することを確認する。
- 連打・押しっぱなし、ネットワーク切断、再接続、投影リロードを行い、最後の公開画面を保持した後に最新の公開状態へ復帰することを確認する。
- 写真などの静的素材は先読みされても、未公開の正解・順位が投影側のデータや画面に含まれないことを確認する。
- 司会者と操作担当者で役割を決め、開始・待機・全画面・休止防止・短縮モードを事前に試す。

### 司会者の読み上げ例

- 解説:「この答えにまつわるお話を、ふたりから」
- 順位予告:「第3位の発表です」
- 受賞者案内:「○○さん、おめでとうございます。どうぞ前へ」
- 締め:「皆さま、ご参加ありがとうございました」

## 決定済み事項と未決事項

- **決定済み:** 単一現在セッション、開始時のSQLite transactionスナップショット、全設問 `id ASC`、全参加者を含む採点、1問1点、未回答0点、最新有効完全revision、標準競技順位、同点全員同時発表、空順位段階のスキップ。
- **決定済み:** admin認証は参加者cookieと分離した `ADMIN_PRESENTATION_PIN` / `ADMIN_PRESENTATION_SESSION_SECRET` によるHttpOnly署名cookie。Origin/CSRF検証、admin API認可、no-storeを必須とする。未設定時はfail closed。
- **決定済み:** admin GETは完全スナップショット、投影GETは公開済み設問回答か現在の入賞順位だけを返す。操作再送は `operationId` で冪等化し、状態競合は409とする。
- **決定済み:** `previous` は永続stage cursorだけを戻し、採点snapshotは保持する。最初の状態では409。`hide` / `show` は永続 `projectionHidden` を操作し、hidden時の公開API応答は `{ state: 'standby' }` のみ。開始前からhide可能。
- **決定済み:** `finished` から `previous` する場合は3→2→1の公開順で最後に存在した入賞順位へ戻し、入賞者がいなければ `podium_preview` へ戻す。
- **決定済み:** `presentationMode` は既定 `full`、`short` の2値をsession DBに永続保存し、開始前から `setMode` で変更可能。短縮時もstage進行と採点を変えず、公開する正解段階で解説だけを省く。
- **未決:** 本番セッション完了後の新たな披露宴/再開催をどの運用で作るか。今回のP0 APIにはリセット機能がない。
- **未決:** 同じ表示名の参加者を司会者・投影画面上で区別する表示方法。
- **未決:** 投影方法と実際のスクリーン比率、素材（ふたりの写真・エピソード）の有無。
- **決定済み:** P0は既存 `explanation` を投影画面に最大4行で表示し、管理画面では全文を確認する。P0では別の要約や司会メモを設けない。
- **P1:** 投影用要約と司会者用メモの別フィールド、作成・確認・承認の運用を決める。
