# 問題画面のマークシート風 UI 計画

> **状態:** 実装済み（受入基準 #7 の200%実ブラウザーズーム確認は未完）。今回の実装では推奨案Aを確定し、紙面の落ち着きと検定操作の明確さを `/answer` に適用した。

### 決定事項

- UI案は **A. 単問表示を維持し、紙面とマーク表現を加える** とする。
- 適用範囲は現行の `/answer` 単画面とし、他の問題画面や新しい表示モードへ広げない。
- 既存の選択・明示確定・`POST /api/answers`・成功後の次問というフローを維持する。API契約は変更しない。
- 実装範囲は設問と選択肢の native radio/fieldset/legend、選択・送信状態、進捗表示、フォーカス、レスポンシブな紙面表現、および関連仕様・テストの同期とする。
- 正誤、正答、解説、得点、合否は受検中・完了画面ともに追加しない。

## 現状

/answer は5問を1問ずつ順番に表示する。利用者は選択肢を選び、明示的に「回答を確定する」を押した後、現在の問題の回答を POST /api/answers に送る。回答確定前は選択を変更でき、送信中は選択肢をロックする。送信失敗時は選択した回答を保ち、再送を案内する。画面には設問位置とサーバへの記録成功数を分けて表示し、回答済み・現在・未到達の5段階を示す。

現在の選択肢は src/components/ChoiceButton.tsx の button と aria-pressed で、角丸の行・選択肢ラベル・本文・選択中表示を持つ。機能は明確だが、選択肢を丸く塗りつぶす紙のマークシート感や、設問用紙としての整った見た目は弱い。現行フローと既存 API の回答値を保ちつつ、選択箇所・確定操作・進捗が試験中に読み取りやすい表示へ整える。

## 目的と範囲

- 問題画面を、印刷された試験用紙を思わせる白系の紙面、控えめな罫線、明確な設問番号で整える。
- 選択肢ラベルを丸または楕円のマークとして表示し、横に本文を並べる。現行の選択肢文字・順序・回答値は維持する。
- 回答選択と確定・送信状態を、タッチ、キーボード、読み上げのいずれでも理解できるようにする。
- 「問題を1問ずつ選択 → 明示確定 → POST → 次問」の順序を維持する。
- 本計画の対象は /answer 問題表示。試験中の正誤、得点、解説、合否は追加しない。

### 今回扱わない拡張

見直しフラグ、前の問題へ戻る操作、スキップ、一括提出、タイマー、新しい検定モード、回答内容付きの解答シート一覧は初期導入に含めない。これらは仕様・操作・APIへの影響を別途検討する拡張候補とする。

## UI 案の比較

| 案 | 内容 | 利点 | 留意点 |
| --- | --- | --- | --- |

| B. 5問を縦一覧にした回答シート | 5問すべてを同一画面に並べ、各設問へ選択肢を表示し、最後に一括提出する。 | 紙の問題冊子に近く、全問の見通しがよい。 | 未到達問、未回答、離脱、送信失敗・再送、一括または段階送信の仕様が必要。現行APIの問題ごとの確定フロー、進捗状態と異なるため、状態管理・受入範囲が増える。 |

推奨は **案A**。視覚表現はマークシートに近づけながら、一問ごとの確定と記録という現在の動作を維持する。native radio を採用した場合は ChoiceButton をそのまま入力要素として再利用できるとは限らない。既存コンポーネントの役割整理を実装時に行う。

## 具体仕様

### 選択肢と回答操作

- 選択肢は fieldset / legend を使い、legend に設問文または「回答を1つ選んでください」を含める。ラジオボタンは問題ごとに一意な name を共有し、回答値は既存 selectedIndex と同じ選択肢 index に対応させる。
- 各選択肢は native radio と明示的な label で構成する。円形マークは未選択・選択中を示し、色だけに依存せず、塗り・輪郭・必要なら「選択中」の文字でも違いを伝える。
- 行全体を label としてクリック可能にし、選択肢ラベル文字（A、B 等）を現行どおり維持する。選択中の文字と枠線には十分なコントラストを持たせる。
- 開始時は未選択。選択のたびにサーバ送信せず一時選択状態だけを更新する。確定前の選択変更を許可する。確定操作時に現在の選択を POST /api/answers し、成功後に次問へ進む。
- 確定操作後の送信中は選択肢と確定 CTA を操作不能にする。二重送信を防ぐ。送信失敗では問題と一時選択を維持し、既存の再試行案内・認証再確認を継続する。
- 回答成功後は次問へ進み、最後の送信成功後は現行の成績を含まない完了画面へ移る。
- native radio のブラウザ標準操作に従う。ブラウザ差のある未選択状態での Shift+Tab 等を独自のキー処理で上書きせず、不要な独自キーボード制御を追加しない。

### 検定らしい紙面

- 背景は白またはごく薄い紙色、設問面は白系、本文色は濃いインク色とする。設問と回答群を細く控えめな罫線でまとめ、装飾を選択操作より目立たせない。
- 設問番号（例「第2問」または「設問 02」）を情報階層上で明確にする。番号は既存の問題順を示し、試験科目・級・得点を示唆する記号は追加しない。
- 選択肢ラベルは丸または楕円の輪郭内に置き、本文と横並びにする。選択中は丸印の塗り、行の背景または枠、文字による状態のうち複数の手掛かりを併用する。
- 「回答済み」「現在」「未到達」の5問状態は番号と文字で伝える。ステップは移動可能なタブやリンクに見せず、クリック不可の一覧として表示する。回答内容は表示しない。
- 確定 CTA は回答群の後に置き、未選択時は disabled にするか既存の送信処理に合わせて無効化し、選択が必要なことを近接テキストでも案内する。送信中は「回答を記録しています…」を使い、busy 状態を伝える。
- 視覚的な紙面と機能状態を分け、受検中に正誤・解説・得点・合否が見えない状態を維持する。

### サイズ・レスポンシブ・フォーカス

- 各選択肢行と主要な CTA は高さまたは操作領域を **44 CSS px 以上**にすることを本案の設計目標とする。これは WCAG 2.2 AA のターゲットサイズ最小値（例外条件あり）の **24 × 24 CSS px** という基準と区別する。
- 320 CSS px 幅と 200% 拡大時に横スクロールを発生させず、日本語の問題文・選択肢が読めること。選択肢ラベル・マークが本文の折り返しを妨げない。
- 画面幅に応じて選択肢は1列とし、設問本文と回答操作を優先する。レイアウト上の左右カラムは設けない。
- ラジオ、選択行、CTA にキーボードフォーカスが視認できるリングまたは同等の輪郭を付ける。フォーカスリングを罫線やマークシートの塗りで隠さない。
- CTA を sticky にする場合は候補実装で覆いを検証し、フォーカス先、エラー表示、送信中表示を隠さないこと。初期設計では通常フロー内に配置する。
- 次問へ移ったときは既存のフォーカス移動方針を保ち、次の設問見出しへフォーカスを移す。新しいライブ領域を追加する場合、同じ内容を複数回読み上げないようにする。

### 状態別表示

| 状態 | 表示と操作 |
| --- | --- |
| 初期表示 | 現問と選択肢を表示。ラジオは未選択、確定不可。 |
| 一時選択 | 選択肢の印・行・文字で選択中を表示。別の選択肢へ変更可能。 |
| 送信中 | 操作をロックし、「回答を記録しています…」と表示。確定操作の重複を受け付けない。 |
| 送信失敗 | 現問と選択を保持し、エラー理由と再試行操作を提示する。回答状態を成功扱いにしない。 |
| 記録成功後 | 現行どおり記録済み数を増やし次問へ進む。回答内容を一覧へ露出しない。 |
| 完了 | 最後のPOST成功後、既存の「回答完了」画面を表示する。採点情報を加えない。 |

## 受け入れ基準

1. /answer は現行どおり1問ずつ表示し、既存順序、5問の状態、回答確定、POST、次問への進行を維持する。
2. 選択開始時は未選択で、選択肢を1つ選ぶまで確定操作ができない。選択確定前は他の選択肢へ変更できる。
3. 選択肢は設問ごとの fieldset / legend と native radio、明示的な label で読み上げられ、各行全体から選択できる。ラベル文字と回答 index の対応は現行どおり。
4. 選択中が丸印の塗り等の視覚表示と文字・輪郭で分かり、色のみを手掛かりにしない。キーボードフォーカスが明瞭に見える。
5. 送信中は選択肢と CTA がロックされ、二重送信されない。POST 成功でのみ記録済み件数を増やし、失敗時は選択内容と問題を維持して再試行できる。
6. 選択行・CTA の操作領域は設計目標の44 CSS px以上を満たす。WCAG AAの24 × 24 CSS px最低基準と混同しない。
7. 320 CSS px幅、200%拡大、長い日本語の問題文・選択肢で横スクロールやラベルの重なりがなく、すべての操作に到達できる。
8. sticky CTA を採用する場合も、フォーカス位置、設問文、エラー、送信中状態を覆わない。採用しない場合は通常スクロールでCTAへ到達できる。
9. 次問表示後に設問見出しへフォーカスが移り、同じ状態説明を重複して読み上げない。native radio の標準的なキー操作を妨げる独自制御を行わない。
10. 現問・回答済み・未到達の進捗は文字でも識別可能で、クリック可能な問題移動と誤解されない。
11. 受検中に正誤、正答、解説、点数、合否を表示しない。完了画面も現行の中立的な回答完了表示を維持する。
12. 仕様書の R2・R5、Components、API節（APIに変更があった場合のみ）が実装と一致している。

## 決定済みの適用方針

案Aを現行 `/answer` に適用する。紙面の外観と、選択・明示確定・送信状態の分かりやすさを両立する。単問表示、現行順序、既存API、回答値、成功後の進行を維持し、他の表示モードは追加しない。
