# 回答中の設問ナビゲーション計画

> **状態:** 実装済み。回答中の共通ヘッダー領域に設問ナビを表示し、設問ごとのサブ説明文を削除した。回答完了画面には設問ナビを追加せず、回答中以外のホーム導線を維持した。受入基準はすべて最終監査で合格。

## 背景と目的

回答中の画面では、設問へ移動するためのページ内ナビゲーションがすでに `QuizRunner` にある。一方、全ページ共通の sticky header には「ホームへ」リンクが表示されている。回答中にそのリンクが設問間の移動に使える領域を占めるため、回答中だけホームリンクを外し、同じ上部領域に各設問への移動ボタンを配置する。

各設問の選択肢の下に表示しているサブ説明文も不要との要望がある。`QuizRunner` の各設問にある未選択時・選択後の説明文を取り除き、説明文を参照する `aria-describedby` も合わせて削除する。設問番号と問題文、全体の未回答案内、回答状態表示は残し、選択肢のラジオ群の accessible name と選択操作を維持する。

各設問の問題文は見出しと fieldset の legend の両方に含まれるため、画面上では見出しに一度だけ表示する。legend はラジオ群の accessible name として残し、視覚的に隠す。

完了画面に設問ナビゲーションは追加しない。回答中以外の画面が持つホームへの導線は維持する。

## 現状と前提

- `src/app/layout.tsx` は Server Component で、sticky header 内に `NavLink` による「ホームへ」リンクを全ページ共通で描画する。
- `src/app/answer/quiz-runner.tsx` は Client Component。回答中の表示分岐には `aria-label="設問へ移動"` の設問ナビがあり、全5問へのリンク、回答済み状態、`jumpToQuestion` によるスクロールと設問見出しへのフォーカス移動を実装済み。
- 各設問には可視の問題文見出しと fieldset の legend があり、問題文が視覚的に重複している。見出しを可視のまま保ち、legend はラジオ群の accessible name として残して視覚的に隠す。
- 各設問の fieldset は `aria-describedby` で `choice-instruction-${question.id}` を参照し、その段落には未選択時「まだ回答していません。選択肢を1つ選んでください。」、選択後「回答を選択しています。確定前に変更できます。」と表示する。これらのサブ説明文を削除する際は対応する `aria-describedby` も取り除き、存在しない ID への参照を残さない。
- 完了表示の分岐には設問一覧がない。
- 推奨する最小構成は、共通 header を小さな Client Component に切り出し、`usePathname` で `/answer` の共通ホームリンクを表示しないこと。回答中のナビは `QuizRunner` が担当する。回答状態を Provider で header に注入する構成は、状態同期と後始末を増やすため採用しない。
- RootLayout 自身は Server Component のままとし、pathname 判定を持たせない。
- `/answer` 配下の完了・ログイン・問題不足・エラー等にもホーム導線が必要な場合は、それらの分岐で導線の所有者を明示する。回答中のナビを共通 header に移す際、設問描画のない状態からホームへ戻れなくならないよう `answer/page.tsx` と描画分岐を実装前に確認する。
- 「同じエリア」は現在の sticky 上部領域を指す暫定解釈。回答中だけ設問ナビで置き換え、共通 header の高さ・余白・sticky 挙動を維持する。

## 実装時の確認事項（解消済み）

- 対象は回答中の共通ヘッダー領域とし、設問ナビで「ホームへ」を置き換えた。完了画面は対象外のままとした。
- `/answer` の設問描画がない状態でもホームへ戻れる導線を維持した。
- 狭い画面での表示、スクロール先の見出し位置、フォーカス移動、回答保持を実装と E2E で確認した。
- 現行 Next.js ガイドを確認してから実装した。

## 実装方針

1. 実装前に `node_modules/next/dist/docs/` の現行 Next.js ガイドを確認する。特に Client Component と `usePathname` の利用規約を確認する。
2. RootLayout の Server Component 境界を保ち、header の表示責務を専用 Client Component へ切り出す。`/answer` では共通 header の「ホームへ」を表示せず、それ以外の既存画面では維持する。
3. 回答中に表示されている既存の設問ナビを sticky header 内の同じ領域へ移すか、同じ状態・操作を保ったまま header 側で描画できる形に整える。回答済み/未回答の表示、設問 ID、クリック時の scroll と focus の挙動を維持し、二重表示を避ける。
4. 設問ナビが回答中分岐の状態を必要とする場合、状態を無理に RootLayout へ引き上げない。`QuizRunner` をナビの所有者にする推奨案を維持しつつ、sticky 上部に表示できるコンポーネント構成を選ぶ。`/answer` の非回答状態でホーム導線が必要なら、その表示分岐が所有する。
5. 固定 header の高さを考慮し、設問へ移動したとき見出しが header に隠れない scroll offset を保つ。320 CSS px 幅でもボタンが読みやすく、操作できる配置にする。
6. 各設問の問題文は可視の見出しに一度だけ表示し、fieldset の legend はラジオ群の accessible name として維持しつつ視覚的に隠す。選択肢下にある未選択時・選択後のサブ説明段落と、それを参照する `aria-describedby` を削除する。設問番号、全体の未回答案内、回答状態表示、選択操作を保つ。
7. `openspec/specs/stcirt/spec.md` の R3、R5、Components を実装と同期し、回答中の設問間移動と回答状態表示を仕様へ反映する。サブ説明文を削除する変更が仕様上の要件にも影響する場合は、Requirements と Components も実装に合わせる。

## 検証と受け入れ基準

- 回答中は上部の「ホームへ」がなく、同じ sticky エリアに全設問への移動ボタンが表示される。
- 設問ナビは回答済み/未回答を既存どおり示し、押すと対象見出しが header に隠れず表示され、キーボード操作でもフォーカス位置が分かる。
- 設問移動では選択済み回答が保持され、回答の保存・送信や回答データの初期化を起こさない。
- 320 CSS px 程度の幅で設問ナビが横にはみ出さず、各ボタンを操作できる。
- 回答中以外の既存画面ではホームへの導線が維持される。完了画面には設問ナビを表示しない。
- 各設問の問題文は可視の見出しに一度だけ表示され、legend は視覚的に隠されつつラジオ群の accessible name として維持される。未選択時・選択後のサブ説明文が表示されず、それらを参照する不要な `aria-describedby` や存在しない ID 参照が残らない。
- サブ説明文を削除しても各ラジオ群の accessible name、設問番号と問題文、全体の未回答案内、回答状態表示、および選択操作が維持される。
- `tests/answer/quiz-runner.test.tsx` と `tests/e2e/answer.spec.ts` で、上記の nav 表示・route ごとの home 表示・scroll/focus・回答保持を意味のある形で確認する。
- 仕様書の Requirements / Components と実装が一致する。
- テスト実装と実行は分ける。テスト実行、format/lint/type-check、spec refs、必要な E2E は Orchestrator がリポジトリの検証ゲートとして実行する。
