# Data lifecycle and provider boundary

This guide records the data behavior visible in the repository and complements the data model and provider contract in [`openspec/specs/stcirt/spec.md`](../openspec/specs/stcirt/spec.md). It does not establish a retention period, deletion guarantee, legal basis, or backup policy. Those decisions are open in [the decision register](decisions/open-items.md).

## Data and observed lifecycle

| Data                                            | Repository use                                                                                                                                                                                                                                                               | Unresolved policy                                                                                                                                      |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Participant display name and normalized name    | Stored in `exam_participants`; signed participant cookie identifies the participant. The sign-in rate limit stores an HMAC fingerprint rather than a name or IP address.                                                                                                     | Normal retention, correction, deletion, and account/contact process.                                                                                   |
| Confirmed answer set and revision history/state | Current submission answer rows are updated in place on correction; assessment records and operation records support revisions and idempotent retries. Unconfirmed drafts remain client-side. The repository does not define how long operation payload records are retained. | Retention and deletion of current or historical records.                                                                                               |
| Presentation snapshot                           | Aggregation copies question, answer, score, rank, and participant display-name data into shared snapshot tables.                                                                                                                                                             | Snapshot retention and deletion after an event.                                                                                                        |
| Free-text answer and grading data               | Q5 question, expected answer, answer text, rubric, and model are sent to the configured provider. The database also stores assessment status, raw/normalized score, confidence, version, and retry metadata.                                                                 | Whether and how participants are informed, provider retention terms, retention/deletion at the provider, and whether additional controls are required. |
| Credentials and signed cookies                  | PINs and secrets are read from server environment; signed cookies carry session identity and expiry. Secret values are not persisted in product tables or this documentation.                                                                                                | Credential owner and rotation procedure.                                                                                                               |

Legacy `knowledge`, `questions`, and `answer_logs` tables remain in the schema for compatibility. The current exam application uses its dedicated `exam_*` tables and does not read or write the legacy study records as product data. Migration 0011 resets specific exam data; it is not a general data deletion mechanism.

## Provider boundary

The JEV adapter sends the current Q5 `question`, `expected_answer`, submitted `user_answer`, grading `rubric`, and selected `model`. It does not send participant name, participant ID, or authentication cookie. Since answer text is free-form, a participant can include personal information in `user_answer`; the payload boundary does not prevent that. Do not claim that the provider payload is anonymous or PII-free. Current version pairing and score handling are specified in R2/R7 and the JEV retry guide.

## Retention, correction, and deletion

No normal retention period or supported participant-data deletion path is specified in the repository. Backup retention and propagation of a deletion into backups are also unknown. Do not infer a retention period from migration behavior or database implementation. The data-owner and product-owner roles must decide these policies before a retention/deletion promise or feature is added. Until then, mark the policy unresolved and do not state a deletion guarantee.

## Performance and accessibility evidence

Existing local measurements are under `docs/performance/`. They describe their own test setup and are not production SLOs, remote Turso capacity evidence, or guarantees for concurrent participant counts, p95 latency, availability, or retry backlog duration. These targets have no agreed values. Existing accessibility and responsive requirements such as 320 CSS px, 200% zoom, reduced motion, 44 CSS px controls, and presentation fit behavior remain in the product spec; this guide adds no new target.
