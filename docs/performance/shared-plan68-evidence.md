## P0 decisions and limits

1. **No field telemetry is currently collected or enabled by this work.** Repository inspection found no `web-vitals` dependency or `reportWebVitals`/vitals transport implementation. This is a bounded source search, not proof about external hosting or analytics configuration.
2. **Do not add field collection until its destination and governance are named.** This repository does not establish a telemetry destination, access policy, retention period, deletion process, consent/legal basis, or public privacy notice for performance data. Those are unresolved facts, not implicit approval to collect.
3. Until that decision is made and implemented, field p75 is **not measurable from available project evidence**. Lab results can diagnose regressions but cannot satisfy field acceptance criteria.
4. Do not send names, participant/admin identifiers, cookies/tokens, answer drafts, free text, question/answer payloads, or raw URLs/search parameters. If a later approved field design is proposed, restrict dimensions to metric value/name, route family (never raw path/query), coarse device class, coarse time window, and only an approved random session/page-view key if needed for deduplication. The project must separately decide whether even that key is allowed.
5. No collection destination or retention is selected here. The decision gate is: document the destination, data fields, access, retention/deletion, consent/legal basis, and privacy notice; obtain the required product/privacy approval; then add the smallest implementation and verify the payload contains only approved fields. Otherwise continue without field telemetry and report field criteria as not assessable.

## Baseline protocol and latest synthetic lab comparison

Keep field and lab evidence separate. For every result record commit/build ID, route, operation, device/browser, viewport, input method, fixture/data state, cache state, network/CPU conditions, run date, sample count, metric definition, and raw artifact location. Never compare unlike builds, fixtures, or conditions as a before/after result.

| --------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| `/answer`             | entry/session and saved-submission resolution; choose answer / move question; submit confirmed answers | touch and mobile keyboard separately; record viewport and device/browser | pointer and keyboard separately; record viewport and device/browser |
| `/results`            | initial authenticated/unauthenticated view; manual refresh; visibility-triggered refresh               | touch; record session state and refresh outcome                          | pointer and keyboard; record session state and refresh outcome      |

| `/admin/presentation` | authentication; each distinct high-impact mutation (aggregate/start/reset/hide/publish)                | touch; use a non-production fixture/environment                          | keyboard and pointer; use the same fixture/environment              |

Each cell means a future measurement run, not a completed check. For lab diagnosis use the same pinned browser/device profile, viewport, build, seeded fixture, cache state, and network/CPU profile for baseline and comparison; collect browser Performance trace (input delay/processing/presentation and long tasks), React Profiler where relevant, and initial JS transfer per route. Repeat each scenario at least 5 times and report all runs plus median and p75; use this only as reproducible lab evidence, never as field p75. Do not run mutations against production data.

For a future field p75 acceptance report, group by route family and coarse device class, report valid page-view count and measurement window, and calculate p75 with a 95% bootstrap confidence interval. Proposed sufficiency gate for this plan: at least 200 valid page views in each reported route/device group and a 95% interval width no greater than 40 ms for INP; otherwise label the group **insufficient sample / not assessed**, with no pass claim. This is a plan-level operational threshold, not a measured result or an industry guarantee. Diagnostic per-operation event latency must be separately defined and is not INP. Report missingness and do not pool unrelated routes/device groups to reach the threshold.

The protocol was exercised once for `/results` in an isolated synthetic loopback lab: baseline first, then migrated Cache Components candidate, n=5 per owner/assisted × fresh-context/reload group, same harness and synthetic fixture, with the disposable SQLite database recreated for each run. The comparison is exploratory; baseline-first order is fixed (not counterbalanced), so server/process warmness can bias results. The harness bound only to `127.0.0.1:3001`, blocked external browser requests, used synthetic participants/data and an ephemeral session secret, and did not use `.env.local`, remote Turso, credentials, or production data. It did not capture response payloads in the comparator JSON.

`first_results_heading_frame_proxy_ms` is navigation-relative `performance.now()` on the second nested `requestAnimationFrame` after `#answer-details-heading` has a non-empty client rect and computed `display`/`visibility` are visible. This is a visibility/frame proxy, not a paint timestamp. FCP and LCP observations use navigation-relative timing. Most last-observed LCP start times match FCP, but candidate sample 3 differs in `owner_reload` (LCP 424 ms vs FCP 68 ms), `assisted_fresh_context` (440 ms vs 64 ms), and `assisted_reload` (412 ms vs 60 ms). These values are recorded without interpretation; capture is bounded (500 ms quiet window, 3 s cap), so it does not establish terminal LCP. CLS has observer support in all 5 samples per group and 0 entries; values are zero only over its bounded capture window. RSC measurement sees no `_rsc` response, so it is `NOT_OBSERVED`, not zero bytes.

Plan targets remain field p75 INP ≤200 ms, LCP ≤2.5 s, and CLS ≤0.1. This synthetic `/results` lab comparison does not assess field p75, per-operation INP, or other routes. The proposed 200 pageviews per route/device group and 95% confidence-interval criterion remains unmeasured; field telemetry has no destination/privacy/governance approval and is not enabled. No plan-level field target is met or failed on this evidence.
