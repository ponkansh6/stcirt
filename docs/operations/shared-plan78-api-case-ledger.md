## Audit boundary and reading key

Each row identifies the source line/title and observed route/client assertions. The contract references are to the current OpenSpec route/API sections where applicable; where no dedicated route section exists, the linked requirement and the exact route implementation are cited. `Keep` means the existing case observes a distinct contract/fault boundary worth retaining; it is not a claim of exhaustive coverage. `P0–P3` describes the consequence of losing the case's stated guarantee, not a measure of assertion count.

These are API handler/client tests with repository, auth, rate-limit, scope, Next cookie, or `fetch` boundaries mocked as shown. Their assertions establish route status/body/header/forwarding/order and client request/schema behavior only. They do **not** establish database persistence/transaction semantics, repository correctness, real HMAC/signature verification, or durable session-cookie behavior; DB/repository and security unit tests own those semantics. The former API-ANS-1 selected-index case was retired with the single-answer route; its historical pass is not part of the current ledger.

Owner for every active row: Fixer for a future test implementation change; root/Orchestrator owns verification. Historical run results predate the current inventory. `pnpm test -- <source-path>` remains the suggested focused command for a future change; it was not run separately for every API source file. No row is on hold. Rows marked Improve identify a concrete existing weakness/fix already made; they are not a request for further source edits in this docs-only pass.
