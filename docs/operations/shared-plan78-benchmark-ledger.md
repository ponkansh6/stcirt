All latency scenarios create a temporary, migration-backed, file-backed SQLite fixture and invoke repository functions or route handlers in-process. They report local operation duration and count-only Drizzle statements; they do not measure remote Turso round-trip time, HTTP wire overhead, or browser-perceived latency. The latency benchmarks report p50/p95 (answer routes and scaling also report SQL count summaries); they do not enforce performance thresholds. Presentation operation scenarios run 40 samples each and keep fixture preparation and assertions outside the timed section. Snapshot scaling runs two warmups and 20 measured aggregations per dataset; every sample resets presentation-side rows in foreign-key-safe order, reuses the same source fixture, and asserts exact persisted questions/entries. The assisted and answer route scenarios run five warmups and 20 measured iterations each. On 2026-10-18, all four suites passed 53/53 registrations with zero skipped or runtime-skipped cases; exact commands and output files are recorded below.

Priority: P2 describes measurement-quality improvements, not correctness blockers. The 46 P2 cases are implemented and passed; P3 cases remain retained probes.
