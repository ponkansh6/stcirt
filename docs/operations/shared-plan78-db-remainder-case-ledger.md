## Resolved Holds, limitations, and review notes

- **Resolved — unsupported persisted presentation state:** R7 specifies that both `advance` and `previous` reject unknown persisted state with generic 409 `Presentation state is invalid`; session state and operation history remain unchanged. DB78-PRES-049 exercises both actions within the existing runtime case. Passed in the 3-suite / 108-case focused run and prior 1,111-case full run.
- **Presentation test grouping:** this suite has broad end-to-end repository cases and shared fixture helpers. Existing case assertions remain valuable, but some large tests combine multiple transitions; a future P2 split could improve failure localization. No split was chosen in this pass because it would add churn without a demonstrated missing guarantee.
- **Independence:** static expected question IDs, statuses, privacy fields and migration schema values are authored in test source. Presentation helpers sometimes derive fixture identifiers, ordering, or summary values from seeded rows; treat those assertions as internal consistency, not an independent oracle for scoring. Score/rank assertions with literal expected values provide the independent scoring oracle.
- **Verification:** the historical pre-retirement full Vitest coverage+JSON run passed 1,159/1,159 cases across 73 files, with zero skipped cases; all four coverage metrics were 100%. The then-current 177 cases in this ledger (now 174 active after three `getNextQuestion` retirements) and 42 answer/JEV cases in the linked ledger passed in that run. The subsequent 1,111-case run passed the prior active inventory; the final post-retirement 1,108-case run also passed across 64 files with 100% statements (3,774), branches (3,365), functions (524), and lines (3,424). The earlier 1,157-case JSON run was an intermediate snapshot before two final cases were added; it is not authoritative. Targeted run history is recorded by the orchestrator in the main ledger. This document itself has not been separately test-validated.
- **Coverage limits:** no production DB connection was used. Bootstrap is mocked; repository and migration behavior uses temporary SQLite. These SQLite cases do not establish Turso concurrency/locking equivalence. Race tests deterministically inject actual local unique conflicts or controlled transaction order; they are not multi-process stress tests. The migrations suite has a hand-authored minimal legacy schema case for migration 0011, not a full production backup replay. Migration schema assertions check the new 0001–0003 fresh schema columns/types/nullability/PK/index/FK; they do not assert each index column definition or every `ON UPDATE` action.

Case names/counts come from the JSON runtime manifest; source links point to the test blocks whose assertions were inspected. No E2E or benchmark cases are part of this DB remainder ledger.
